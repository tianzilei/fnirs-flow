# Public Repository Sync Specification

This document defines how to sync the private development repository into the
public `fnirs-flow` repository and what must be checked after every sync. The
public repository is a code-oriented release tree. It must remain installable,
testable, and free of private manuscript, literature, sample-data, output, cache,
and platform metadata content.

## Scope

The public tree is generated by `scripts/sync_public_release.py`. The script uses
an explicit whitelist instead of copying the whole development tree.

Included content:

- Root release files: `.gitignore`, `CHANGELOG.md`, `PUBLIC_SYNC_SPEC.md`,
  `README.md`, `ai_flow_generation_guide.md`, `cli.py`, `environment.yml`,
  `pyproject.toml`, `LICENSE`, `LICENSE.md`, and `THIRD_PARTY_NOTICES.md`
- Public source directories: `config/`, `configs/`, `fnirs_flow/`, `schemas/`,
  and `tests/`
- WebUI release source: selected `webui/` package metadata, Vite/TypeScript
  configuration, `webui/src/`, `webui/tests/`, and `webui/e2e/`
- Prebuilt WebUI runtime assets under `fnirs_flow/resources/webui/dist/`, which
  are required for wheel packaging and API static serving
- Public documentation: `docs/README.md`,
  `docs/specs/fnirs_flow_public_api.md`,
  `docs/specs/method_atom_parameter_ui_contract.md`,
  `docs/specs/package_profile_spec.md`, and
  `docs/specs/mvp_task_glm_acceptance_checklist.md`
- Public scripts listed in `PUBLIC_SCRIPT_FILES` inside
  `scripts/sync_public_release.py`
- Public CI and release tools listed in `PUBLIC_TOOL_FILES` inside
  `scripts/sync_public_release.py`
- Generated OpenAPI contract `generated/openapi.json`, used to verify the
  checked-in WebUI API types
- Generated release metadata: `PUBLIC_RELEASE.md` and
  `PUBLIC_RELEASE_MANIFEST.json`

Excluded content must never be present in the public repository:

- `.agents/`, `.mimocode/`, `.tmp/`
- `References/`, `Sample/`, `audit/`
- `docs/literature/`, `docs/manuscript/`
- `legacy/`, `outputs/`
- caches, virtual environments, build artifacts, logs, backups, and platform
  metadata files

The public repository owns `.git/`, `.github/`, and `.gitattributes`; a clean
sync preserves these paths.

The public repository does not ship hosted CI/CD workflows. Maintainers run
the documented validation commands locally and publish verified release
artifacts manually. Other repository-owned configuration under `.github/` may
be retained.

## Language Policy

The public repository uses English for all documentation and code comments.
Public Markdown, reStructuredText, inline comments, block comments, and
docstrings must not introduce Chinese text. If upstream private notes contain
Chinese descriptions, translate them to clear English before syncing or
committing the public repository.

## Sync Command

Run from the development repository root.

```bash
python scripts/sync_public_release.py --target /path/to/public/fnirs-flow --dry-run
python scripts/sync_public_release.py --target /path/to/public/fnirs-flow --clean
```

Use `--dry-run` first on every sync. Use `--clean` for the actual sync so stale
files are removed while `.git/`, `.github/`, and `.gitattributes` remain intact.

Use `--init-git` only when creating a new public target directory. Do not use
`--no-manifest` for a normal public release because the manifest is part of the
public verification surface.

## Pre-Sync Checklist

- The development repository has the intended source changes committed or
  clearly reviewed. Do not sync accidental local edits.
- `README.md`, `CHANGELOG.md`, `docs/README.md`, public specs, licenses, and
  third-party notices match the release being published.
- New public files have been added to the appropriate whitelist in
  `scripts/sync_public_release.py`; private or internal files have not been
  added by broadening directory copies.
- Any new dependency has corresponding license/notice coverage in
  `THIRD_PARTY_NOTICES.md`.
- Any claim about test counts, backend support, datasets, or limitations is
  current and supported by the latest validation run.
- Documentation, comments, and docstrings in public files have been reviewed for
  English-only wording.

## Post-Sync Audit

After the clean sync, inspect the public repository before committing or
publishing it.

```bash
git status --short
python scripts/sync_public_release.py --target /path/to/public/fnirs-flow --dry-run
```

Confirm these conditions:

- `PUBLIC_RELEASE_MANIFEST.json` exists and reports the expected copied file
  count.
- `PUBLIC_RELEASE.md` exists and describes the public release scope.
- No forbidden path exists in the public tree.
- No generated output, sample dataset, manuscript draft, literature extraction
  table, reference repository, local cache, or platform metadata file appears in
  `git status --short`.
- `.github/` and `.gitattributes` were preserved from the public repository.
- `.github/workflows/` does not contain hosted CI/CD workflows.
- Public documentation links resolve to files that actually exist in the public
  tree.

Recommended validation commands:

```bash
pytest -q
ruff check cli.py fnirs_flow tests scripts tools
cd webui && npm install && npm run test:unit && npm run build -- --mode development
```

When time or environment constraints prevent the full suite, record the skipped
checks and the reason in the release notes or handoff.

## Required Markdown Updates After Every Sync

Every public sync must end with a documentation pass in the public repository.
Update public Markdown before committing the public repo.

Required files to review:

- `README.md`: version label, installation commands, CLI examples, WebUI
  instructions, project structure, capability claims, and test-count claims
- `docs/README.md`: `Last updated` date, public documentation index, validation
  baseline, and public release contents
- `CHANGELOG.md`: release entry, validation evidence, breaking changes, known
  limitations, and migration notes
- `PUBLIC_RELEASE.md`: generated by the sync script; verify the scope still
  matches the actual release policy
- `PUBLIC_SYNC_SPEC.md`: update when the sync whitelist, forbidden paths, audit
  process, or public release policy changes
- `THIRD_PARTY_NOTICES.md`: update when dependencies, bundled frontend packages,
  or backend integrations change

Public Markdown must not mention private local paths, unpublished manuscripts,
internal work plans, extraction worktables, private sample locations, or
development-only audit folders. It may mention that those materials are
intentionally excluded.

## Commit Gate

Commit or push the public repository only when:

- The post-sync audit is complete.
- Required public Markdown has been reviewed and updated.
- Public documentation and code comments use English only.
- `git status --short` contains only intentional release changes.
- The public repository can be understood without access to the private
  development repository.
- Any incomplete validation is explicitly documented.
